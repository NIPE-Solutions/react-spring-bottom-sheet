# React Spring Bottom Sheet v4.1 Implementation Plan

**Goal:** Produce a non-breaking, release-ready v4.1 with trustworthy tests, confirmed bug fixes, clean builds, secure runtime dependencies, React 18/19 compatibility, and automated CI.

**Architecture:** Protect the current public component with tests before making targeted fixes. Extract only pure derivation logic where isolation improves testing; retain the existing portal, XState, React Spring, and gesture architecture until the separately designed v5 rewrite.

**Tech Stack:** React 18/19, TypeScript, XState 5, React Spring 8, Vitest, Testing Library, Playwright, Next.js documentation site, npm, GitHub Actions.

**Specification:** `docs/roadmap/v4.1-stabilization.md`

## Global Constraints

- Preserve `BottomSheet`, `BottomSheetProps`, `BottomSheetRef`, all existing props, callback event shapes, defaults, ref methods, and legacy import paths.
- Support React 18 and React 19.
- Do not perform major React Spring, gesture-library, or XState React upgrades.
- Every behavior fix requires a failing regression test before production code changes.
- Project-owned warnings fail CI.
- Shipped runtime dependencies must have no known npm audit vulnerabilities.

---

## File Structure

- `vitest.config.ts`: unit/component test configuration.
- `test/setup.ts`: DOM test cleanup and browser API polyfills.
- `src/**/*.test.ts(x)`: tests colocated with the behavior they protect.
- `playwright.config.ts`: real-browser fixture configuration.
- `e2e/bottom-sheet.spec.ts`: public interaction, focus, animation, and gesture smoke tests.
- `test/package/verify-package.mjs`: install and import the packed artifact as a consumer.
- `.github/workflows/ci.yml`: required pull-request and main-branch checks.
- `src/utils.ts`: pure snap-point behavior.
- `src/hooks/useSnapPoints.tsx`: element and viewport measurement.
- `src/BottomSheet.tsx`: animation actors, ARIA semantics, and public state.
- `src/types.ts`: compatible lifecycle callback typing.
- Build configuration files: clean distribution and documentation builds.
- `package.json` and `renovate.json`: scripts, exports, dependency classification, and automation.
